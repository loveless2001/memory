# BUILD.md — Unified Memory Substrate MVP (M0–M2)

Handoff brief for implementation. The authoritative design document is
`unified_memory_substrate_spec_v0.3.6.md` (referenced below as "the spec"),
but **build only what this brief scopes**. Where this brief and the spec seem
to disagree on scope, this brief wins; where they disagree on semantics
(schemas, invariants), the spec wins.

---

## 1. Mission and scope

Implement milestones **M0, M1, M2** of the spec's Appendix B on the reference
configuration (Appendix B.1): Qwen/Qwen3-4B-Instruct-2507, bf16, single GPU,
HF transformers runtime.

```text
M0  text substrate: raw archive, segmenter, summaries, embedding shadows,
    runtime-gated EXPAND                                    (no training)
M1  compaction/eviction with sink pinning + offline certification harness
                                                            (no training)
M2  NVMe delta checkpoints, hydrate-or-fallback resume      (no training)
```

Deliverable form: a **Python library** with a thin CLI. NOT an HTTP service —
ignore spec §18 entirely; it is a future wrapper, not the MVP surface.

### Do-not-build list (hard scope fence)
- No training runs of any kind (no compactor, no gate, no adapters).
- No vLLM integration (B.7 tier (b)). Tier (a) HF Cache subclass only.
- No channels, soft slots, latent compression, recurrent memory
  (spec §6.3 channel machinery, §15, §16).
- No parallel-decoding / branching runtime (§11.6) beyond CoW checkpoint
  lineage metadata.
- No β/bias channel anywhere (Appendix B.4 policy: β=0 → no custom kernels).
- No performance optimization until all golden tests are green.

## 2. Ground rules

1. **First commit = pinned environment + fingerprint module.** torch,
   transformers, safetensors versions locked. A transformers upgrade that
   touches RoPE/cache code is a `runtime_version` change (spec §4.6): it
   invalidates certification data, not just caches. The fingerprint record
   (schema in §5 below) must be computed and stored before any KV artifact
   is ever written, and every artifact write path must require one.
2. **Tests before features.** The golden tests in §4 are the acceptance
   criteria; write them first (xfail until implemented).
3. **SQLite for all metadata**, content-addressed filesystem store for blobs.
   No Postgres, no queues, no k8s.
4. **Every block gets an embedding shadow and a raw pointer** — the raw
   indexer is mandatory infrastructure (spec §8.1), not an optional step.
   Embedding model: Qwen3-Embedding-0.6B, recorded as `shadow-v1`.

## 3. Build order (risk-ordered, not section-ordered)

```text
P0  env pin, fingerprint module, repo skeleton, golden tests as xfail
P1  CompactedPrefixCache (B.7 tier (a)) + Golden Test 1
    — the highest-risk artifact in the whole build; do it first.
    Semantics: physical cache length K; stored offset (T − K) added to
    continuation positions before RoPE; sink pages always resident.
P2  raw archive + span index + segmenter (turn boundary + 1–2k token cap)
P3  summaries (generated by the base model), shadows, runtime EXPAND
    (selector may be naive top-k over shadows at this stage)  → M0 done
P4  compaction/eviction path: sink pinning (positions 0–3, asserted in
    the compactor path), MemoryBlock creation, offline certification
    harness over the pilot dataset                            → M1 done
P5  safetensors delta checkpoints on NVMe, mmap hydration,
    fingerprint-checked hydrate-or-fallback resume            → M2 done
```

Data: build the B.3 MCQ pipeline against a **1–2k-item pilot** only.
Do not generate the full corpus; that is a later, human-triggered step.

## 4. Golden tests (acceptance criteria)

```text
GT1  Identity round trip (P1 gate — nothing proceeds until green)
     full prefill → snapshot → restore at K = T → continue N tokens.
     Logits match the never-snapshotted continuation within kernel
     nondeterminism tolerance (compare top-k token sets + max prob delta,
     not bitwise). Run at T ∈ {1k, 8k}. This is the only test that
     surfaces spec §12's silent position-corruption failure mode.

GT2  Sink invariant (M1)
     any compaction plan that would evict positions 0–3 must raise before
     touching the cache; checkpoint records sink_tokens_retained; restore
     hydrates sink pages first.

GT3  Fingerprint gate (M2)
     mutate any single fingerprint field on a stored checkpoint → resume
     MUST take the fallback path (summary/full re-prefill), never load KV.
     Parameterize over every field in the fingerprint schema.

GT4  Eviction changes behavior, certification catches it (M1)
     evict a span containing a planted fact; the needle probe over that
     span must flip from correct to incorrect (or to EXPAND) — proving the
     lost-fact instrument detects real loss; and the aggregation-axis and
     pointwise-axis scores are reported SEPARATELY (spec §13.4, §4.7 —
     assert no blended metric exists in the report object).

GT5  Redaction traces the graph (M0)
     redact a source span → every derived artifact (summary, shadow,
     checkpoint pages, consolidated blocks) reachable via derived_from is
     invalidated; a subsequent read of any of them fails closed;
     redaction_generation increments.
```

Definition of done per milestone: its golden tests green + a smoke script
(`examples/`) exercising the milestone end to end on a toy thread.

## 5. Schemas (extracted verbatim from the spec — do not re-derive)

### compatibility_fingerprint (spec §4.6)
```json
{
  "model_id": "model-name-or-hash",
  "tokenizer_hash": "sha256:...",
  "chat_template_hash": "sha256:...",
  "rope_config_hash": "sha256:...",
  "sliding_window_config": "none | local-4096 | hybrid-...",
  "attention_impl": "flash-attn-x.y | paged-attn-x.y | custom",
  "kv_layout": "mha | gqa | mqa | mla_latent",
  "quantization": "bf16 | fp16 | int8 | gguf-q4_k_m",
  "adapter_hash": "sha256:... | null",
  "runtime_version": "vllm-x.y | llamacpp-x.y | custom",
  "compaction_policy_version": "compact-v1",
  "position_policy_version": "pos-v1",
  "channel_registry_version": "memchan-v1",
  "kernel_numeric_profile_hash": "sha256:..."
}
```

Note (spec §4.6): for trained compactors, `compaction_policy_version` must
incorporate the compactor weights hash and `max_certified_depth`. For this
MVP (untrained eviction only) set it to the eviction-policy string + version.
`kernel_numeric_profile_hash`: implement as hash over (kernel/library
versions, dtype + determinism flags) concatenated with a hashed fixed-input
forward-pass probe output at reduced precision.

## 6. Reference constants

```text
model        Qwen/Qwen3-4B-Instruct-2507   (L=36, H_kv=8, d=128, GQA)
KV cost      ~144 KiB/token bf16 → 1.125 GiB @ 8k, 4.5 GiB @ 32k

```
