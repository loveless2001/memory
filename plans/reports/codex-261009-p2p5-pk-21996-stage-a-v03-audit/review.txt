Remaining block: campaign deadline is stored, not enforced across the worker
The remote function samples remaining before _versions_ok(), then uses that
stale value to choose the child timeout. Offline reproduction with a fake clock:
deadline1000; initial time0; version check finishes at1001; the code still starts
a child with timeout910 and returns rc0. This is a code-path counterexample, not
an assertion that actual version import took1001 seconds. A real import delay
can consume the intended margin; the guarantee is currently false.

More broadly, there is no independent absolute whole-worker kill guard covering
Dict RPCs, imports, the child and tar return. Function timeout1560 remains
relative to each execution; default startup has no shorter explicit bound.
The passed deadline and immutable Dict are valuable admission controls, but do
not themselves bound setup/serialization or a late startup's charged tail.
