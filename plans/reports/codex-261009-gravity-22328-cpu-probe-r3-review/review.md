## Launcher error handling and mitigation

The shell wrapper logs condition exits but does not synchronously abort on nonzero exit. It could proceed to the next condition and print ALL DONE/exit0 despite incomplete results. This was reported in channel22333. Claude added a separate fail-stop watcher, independently observed as pid21705, that checks exits.txt every five seconds, kills launcher19449, stops matching r3 scopes on any nonzero exit, and writes CHAIN STOPPED. The command is retained here; the launch record preserves the change. This is an eventual stop with a five-second race window: a next condition may start before the watcher responds. Message22332 explicitly acknowledges that such a partial next condition is preserved. The healthy init was not restarted. Future wrappers should check each exit synchronously; neither this watcher nor ALL DONE establishes successful completion.
