Reviewed frozen `2c99725`, draft SHA `1b69fbebffd3212ad9b103154cf7231a783790ae482b56e4b4fa9407d5ef481d`. The original prereg SHA `0ce61a09…` and grid SHA `d1c045ea…` match; the grid contains exactly 18 unique cell IDs and nine same-arm/same-N seed0+1 pairs. The two-worker A100 topology is a reasonable design direction. **The execution amendment is not cleared yet**, because its recovery and proof rules do not fully specify the behavior required by its claims. This review does not authorize paid work.

1. **Persistent terminal state and single ownership.** PK1 says a failed worker is never restarted, but PK2's complete/checkpoint/nothing classifier would resume a failed worker's checkpoint on a later container restart. Define an explicit durable state machine with FAILED/LOST terminal precedence, INITIAL/STARTED distinction, immutable launch identity, attempt ownership/lease and stale-writer refusal. Previously started work with no acknowledged checkpoint cannot silently become a new initial run. Either persist a step0 state before updates or explicitly register and budget a bounded initial replay. Completed cells still need all original validation gates; a completion flag alone is insufficient. Failed/lost/incomplete cells remain unavailable, preserving the paired-seed and headline limits.

2. **Local atomicity is not demonstrated remote durability.** `training_resume_checkpoint.save_atomic()` performs a local temporary write, fsync and rename; it does not issue a Modal Volume commit. Register immutable checkpoint generations, content hashes, ownership and an acknowledged durable generation pointer. If claiming loss ≤C updates, the next update must wait until the C-step generation is durably acknowledged; otherwise account for the additional durability lag. Define commit failure, interrupted publication, fresh-mount/reload and old-owner behavior. Charge serialization, transfer and commit overhead. [Modal's Volume documentation](https://modal.com/docs/guide/volumes) distinguishes local files from committed data, describes reload behavior and warns about shared-file last-write-wins semantics. Concurrent workers/slots must not publish to the same file.

3. **Explicit training-complete and evaluation-only recovery.** The current trainer's checkpoint hook only saves `0 < step < steps`; for C50/1500 it last saves step1450. PK2 both rejects step1500 and promises not to repeat training if final evaluation is interrupted. Specify a new durable TRAINING_COMPLETE state at `step == steps`, with the exact final weights, config and required telemetry/RNG metadata, plus a consumer that performs zero additional optimizer updates. Cover loss before/during terminal dev or artifact evaluation. Preserve incomplete attempt outputs and publish COMPLETE only after validated artifacts and their durable hashes are acknowledged. `run_pilot` currently creates `out_dir` with `exist_ok=False`, so resumes need fresh attempt directories and a separate canonical validated publication.

4. **Proof of the actual durable restart boundary.** Killing two workers in a still-live container does not test that a fresh container can see the saved checkpoint. The proof must retain producer/consumer container identities and the acknowledged generation hashes, terminate the producer boundary, then consume those exact artifacts through the slot runner in a fresh container. Include training resume across the curriculum transition (shortened schedule explicitly specified), final-training/evaluation-only recovery with zero repeated updates, and previously FAILED cell persistence through slot restart. Declare proof checkpoint cadence and dev-only train/eval seed/config overrides. No registered/artifact/reserved population is permitted.

5. **Complete proof acceptance and admitted scope.** List the exact nine slot types ×two phases, oracle only N32, worker counts, warmup/measured updates, evaluation batches, repeats, thread setting and whole-process bounds. Freeze full expected tensor names/shapes, per-update loss/gradient/final-weight/prediction comparisons, finite handling, relative and absolute near-zero tolerance rules, and determinism-control acceptance. The old run2 checker did not pass-gate every training numeric field, so its tolerance alone does not define the proposed expanded proof. A timing OOM/error/incomplete matrix must also block pricing; correctness failure stops the packed plan. Explain that dev prediction comparisons are engineering evidence and are not a scientific accuracy reading or tuning/selection. Treat ≲$2 as a budget target until the complete charged proof reservation is audited. An infeasible budget does not authorize reducing the matrix after observing data or retrying.

6. **Bounded restarts and whole-app lifecycle.** R3 means four admitted starts total per slot. Bind atomic start claims, persistent deadlines, admission before model loading, worker cleanup, independent watchdog/reaper and scoped app shutdown. Returning from a failed input is not evidence that all paid containers have stopped. Charge all nine slots, every admitted start, queue/startup allowances, checkpoint/evaluation/I/O, readings, builds, reapers and teardown. Specify how per-slot expiry interacts with an app hosting other slots. Preserve shared GPU/container failure evidence; the controller can permit a co-tenant to continue, but cannot guarantee it is unaffected. Mixing P1/P2 after resume and evaluation/training overlap also need an explicit conservative cost/memory basis.

The claim that non-preemptible GPU Functions are unavailable is consistent with the current [Modal preemption documentation](https://modal.com/docs/guide/preemption), despite the installed SDK exposing a general `nonpreemptible` argument. This is not a draft defect.
