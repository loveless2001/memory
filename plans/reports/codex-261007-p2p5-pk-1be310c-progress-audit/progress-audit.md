The six counterexamples below ran against immutable source snapshots using CPU-only fakes. No remote calls, deployment, GPU launches, shared-source edits, or proof-artifact changes were made. Evidence: `probe-control-boundaries.py`, four `frozen-*.py` snapshots, and `independent-control-boundary-probes.json` in this directory. The nine submitted tests passed independently; their log is `independent-new-tests.log`. Those tests do not exercise these failing integrations.

1. **Controller horizon omits sequential readings.** `arm()` computes `max(slot lives, readings life) + 1800`, and v4 prices the same shortened horizon. With the recorded longest training reserve of 31,946.2 s, the controller deadline is 33,746.2 s. Readings beginning at the last training deadline can validly run until 43,025.1 s, even allowing zero validation or setup delay. The probe self-stops the controller while the readings entry remains `not due`, leaving a 9,278.9 s gap. Freeze a complete training-to-validation/setup-to-readings-to-cleanup timeline, account for slot-spawn offsets, enforce a latest readings-start boundary, and reprice the controller lifetime. Individual app deadlines must remain immutable and fit the controller horizon.

2. **An unarmed controller immediately self-stops.** `control_view()` returns `app_id=None` and a future first-tick-plus-1800 deadline. `due()` treats the missing ID as immediately due, so `control_tick()` issues a name-only self-stop on the first tick. Test the complete abandonment path, safely bind the controller's own identity, and distinguish abandonment timing from malformed external registry entries.

3. **Terminal self-stop discards unresolved cleanup.** A target stopper raising a controlled error is recorded, but the same tick still self-stops the controller. The documented next-tick retry cannot occur afterward. Before terminal self-stop, make bounded attempts for all owned active apps and retain unresolved stop/verification evidence. Define and price the bounded cleanup/fallback policy, and prevent later workload admission after controller expiry or terminal failure.

4. **NaN and infinity defeat deadlines.** `register()` accepts both; `due()` returns false for both indefinitely; slot `admit()` accepts each as admission 1. Validate finite, positive numeric deadlines and reject booleans at registration, guard/price ingestion, and admission. A malformed deadline must not authorize GPU work.

5. **Missing IDs become unbound name-only stops.** A registry entry with a deadline but no app ID passes `None` into shared `stop_bound_app`. That helper deliberately skips identity verification for `None`. The integrated mocked probe calls `stop_app("unbound-name")` without any lookup. Refuse or quarantine malformed external entries, preserve the error, and continue valid bound targets; never interpret an unknown external ID as permission to stop by name. The legacy single-app helper's optional-ID behavior is not a safe default for this registry.

6. **One hung stop request starves every later target.** The tick calls stoppers sequentially without per-request bounds. A bounded subprocess probe that blocks sorted target `a` records no attempt for due target `b`. A whole-function timeout does not isolate target attempts; repeated ticks can keep hitting the same first entry. Bound or isolate each request, ensure all due targets receive attempts within the tick budget, and retain outcomes even when one request hangs. No deployment is needed to test this behavior.
