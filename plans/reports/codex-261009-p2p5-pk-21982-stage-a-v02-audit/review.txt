1. Warm container fails on the second distinct arm (BLOCKER)
run_arm_remote always creates /tmp/stage-a-out with mkdir() and never removes it.
The same Modal function can reuse its container for A1 after A0. A1's start key
is consumed, then mkdir raises FileExistsError before the child starts. In the
offline raw-worker reproduction, A0 returns rc0, A1 raises FileExistsError,
only one child runs, and both A0/A1 are recorded as started. This is not a GPU
fit or learning finding. The existing repeated-A0 refusal test does not cover it.

Use a fresh TemporaryDirectory per invocation (cleaned after the tar is built),
or isolated per-arm paths with explicit safe cleanup. Do not overwrite prior
arm artifacts. Add an A0->A1->A2 same-container test with disjoint extracted
outputs, retaining the existing second-start refusal-before-child test.

2. Claimed $3.72 hard cost bound is not established (BLOCKER)
The ledger arithmetic is correct: rate .00066544/s, client5100s cost3.393744,
build .084192, teardown .2395584, sum3.7174944. Its duration and resource
assumptions are not all enforced:
- Per-arm function1560/child1500 timeouts are not one immutable campaign
  deadline. A late call or container restart can receive a fresh timeout.
- The 120s teardown allowance has no enforcing mechanism. Killing the client
  relies on server disconnect detection; a still-live call's configured
